# Limewire 按容量分子任务清理设计

已实现单子任务工作流，不实现自动连续模式。全量名单只扫描一次；按约 500 GiB 可配置逻辑容量分配，每个子任务独立删除、恢复、验收。详细命令见 [README](../README.md)。

## 流程和边界

```text
授权范围、冻结数据、处置 challenge 风险
    ↓
scan 全量落库、数量对账、COMPLETE 封存
    ↓
task create → 固定 OID 名单及快照摘要
    ↓
purge --execute → 查链确认 → 物理批删 → 清元数据 → 逐 OID 记结果
    ↓
verify → 两前缀及本地元数据独立复查 → 逐 OID 记验收结果
    ├─ 请求错误：本对象重试耗尽后记 ERROR，继续其他对象；之后续验
    ├─ 有残留：记 RESIDUE；重跑 purge，再开启整批新代次验收
    └─ 全 PASS：DONE → 操作人生成下一任务

长期无法处理 → 人工 defer（记录原因，不计 PASS）
    → 其余全 PASS：DONE_WITH_EXCEPTIONS → 允许下一批
    → 延期池留账 → 后续显式 task create --retry-deferred
```

一个 SP/清理范围使用一个独立 MySQL 进度库，不是每个子任务创建一个物理 DB。
执行命令默认选择唯一未完成任务，不需要手记 task ID；历史查询和历史复验使用显式 ID。
task create 已有未完成任务就返回它，不悄悄新增任务；purge 必须 --execute，独立 verify 不删业务数据。

### 当前任务与操作防错

- 无当前任务时，`purge --execute` 报错并提示先 `task create`，不自动创建；保留“创建 → 人工看摘要 → 执行”的检查步骤。
- `purge / task resume / task defer` 的可选 `--task-id N` 是当前任务 ID 的断言：在持有执行锁后校验，不一致拒绝执行。脚本建议填入已人工检查的 ID，防止查看摘要后其他人切换了任务。
- `task exclude` 是 `task defer` 的别名，默认当前任务，必须填写原因；不计 PASS、不丢弃延期记录。
- `task create / purge / verify` 选定任务后的首条日志打印 ID、对象数、逻辑容量；关键处理日志统一带 `task=N`，返回错误也保留 ID。
- `verify` 默认当前任务；无待验收任务时报错，不静默成功。历史任务必须显式指定 `--task-id N`：不加 `--restart` 仅导出已有报告，加上才重新验收（要求无其他未完成任务）。
- `status` 默认显示当前任务详情及全局汇总（完成批数、未完成批数、未分配/延期对象）；显式 `--task-id N` 可查看历史详情。

工具不发链上交易、不停计费、不处理全网挑战风险，不允许在目标数据仍持续回写时据断点 PASS 宣称完成。
只支持当前配置的单物理桶；S3 Enabled/Suspended 默认拒绝，purge 和 verify 均可用 --allow-versioned-bucket 显式放行并打印警告，查询状态失败仍拒绝。保持原按 key 删除流程，不新增按版本清理；放行后的 PASS/DONE 仅覆盖当前可见 key 和本地元数据，不代表云历史版本、删除标记或计费空间已清除。

## 容量和冻结名单

| 规则 | 实现 |
|---|---|
| 目标容量 | --target-size，默认 500GiB；按 scan_objects.payload_size 累计 |
| 数量上限 | --max-objects，默认 10000，允许 1..100000 |
| 分配顺序 | OID 升序，到达容量或对象数上限停止 |
| 普通对象 | 最后一个允许略超容量，不精确装箱 |
| 超大对象 | 独立任务，不拆 OID |
| 零字节对象 | 占对象数额度，避免任务无限大 |
| 未满最后一批 | 正常创建 |
| 物理释放量 | 与逻辑容量分开，primary/secondary/旧残留均可能不同 |

scan 对账：源表扫描前计数、扫描后计数、实际读取量、落库唯一 OID 数必须相等，且检查 rows.Err。
正式 scan 计数为 0 时拒绝继续，FinishScan 也拒绝封存 0 行名单；count-only 可显示 0。ALL_DONE 要求扫描行数及名单对象数大于 0，且至少一个子任务已完成；历史空 COMPLETE 名单只警告、不宣称完成。
中断可从头补扫，INSERT IGNORE 不覆盖已有快照；COMPLETE 后禁止再次扫描扩容。
计数对账不能替代 BSDB 已同步及目标集合稳定的运维前提。

create 同一事务写入任务及所有成员，摘要覆盖 OID、payload_size、状态、版本。
默认仅选没有任何历史任务记录的对象。显式 retry-deferred 仅选最近一次分配为延期且其任务已完成的 OID。
事务失败回滚，提交成功响应丢失后可通过默认当前任务恢复。

## 表和持久化状态

| 表 | 作用 |
|---|---|
| task_meta | 单行绑定链/SP/物理桶/SpDB/GNFD bucket，扫描状态与计数 |
| scan_objects | 全量冻结快照 |
| purge_tasks | 容量、对象数、快照摘要、阶段、安全暂停原因及关联 OID、验收代次、done_at |
| task_objects | 联合主键 task_id + object_id；延期决定及逐 OID 验收状态 |
| purge_progress | 每 OID 处理成功/失败、累计删除量、大小对账；不是逐次尝试审计 |
| task_events | 人工 DEFER / RESUME 原因及数据库时间 |

允许延期 OID 被明确重新分配，故 object_id 不是跨所有历史任务的唯一键；保留旧成员用于追溯。
创建事务与同库执行锁保证不会被两个运行进程重复分配。不要直接改表绕开状态转换。
DONE 写入与清除该 OID 的旧 RESIDUE 标记放在同一事务，防止重启反复重排已清理对象。

| 展示状态 | 来源和处理 |
|---|---|
| READY | 阶段未开始 |
| RUNNING / VERIFYING | 执行锁正被占用，结合持久化阶段推导 |
| RETRY_PENDING | 未运行且还有未处理/失败对象；原 purge 重跑 |
| AWAITING_VERIFY | 已处理但尚未完成验收；verify |
| VERIFY_FAILED | 当前代次有残留或查询错误 |
| SAFETY_HOLD | 持久化安全暂停，优先于其他状态 |
| DONE | 完成时间已写入，无延期 |
| DONE_WITH_EXCEPTIONS | 完成时间已写入，有延期；不能等同全量清空 |

不持久化“某进程仍在运行”的结论，崩溃后由锁状态反映；阶段只表示上次进入哪个步骤。
进度库写失败必须报错，不能仅靠日志当作完成。

## 错误处理和安全暂停

- 普通网络/存储/链查询失败：保留内部有界重试；一个对象最终失败即打印 !!! STOP，停止新对象（含队列中未开始项），等待在途对象完成或自身失败并尽量落库，然后非零退出，不自动补跑、不写 SAFETY_HOLD。进度读写失败也停止派发；排障后原 purge 命令续跑，不需 task resume/--retry-failed。收尾时长取决于在途对象，不保证几分钟结束。dry-run 和 verify 行为不变。
- 链查询临时网络故障、429/5xx 和 SpDB 删除/复查临时故障：各最多 3 次应用层尝试，短退避 1 秒、2 秒；SpDB 单次限时 30 秒，删除按 OID 幂等重试。永久权限/参数/对象不存在等错误不重试。失锁或 Ctrl+C 立即取消，包括普通失败收尾期间。
- 查链返回身份/快照不符、key 格式/归属异常：停止派发和在途操作，写 SAFETY_HOLD，不自动补跑。已经发出的请求不可撤回。
- 任务摘要或全局 bucket 身份异常：全局 SAFETY_HOLD，不允许通过延期单个 OID 绕过。
- resume 要填写人工核查原因，保留事件；只解调度暂停，不刷新快照、不放宽校验。异常未解决会再次停机。
- defer 要填写原因，只标记本任务成员延期，不删除其数据，也不计 PASS。与安全暂停直接相关的单个 OID 可明确延期；不相关/全局暂停仍拒绝。
- 快照已变化且不能满足冻结名单的对象：先延期留账，再独立审核新范围；显式重试延期对象仍使用旧快照，不会自动替换。

所有未延期 OID 验收通过后，任务即使有延期也可结束为 DONE_WITH_EXCEPTIONS；报告必须列出延期项。
延期池以 OID 最近一次任务归属为准：未重新分配的继续显示；已重新分配但失败的由新任务负责。未分配数、未解决延期数、未完成任务均为零才可显示 ALL_DONE。

## 验收及断点

首次 verify 覆盖本任务全部未延期 OID，检查 s&lt;oid&gt;_、e&lt;oid&gt;_ 是否为空及本地元数据。
只需每前缀探测一个 key，不逐个 HEAD，也不计算剩余总字节；有一个就是 RESIDUE。

验收结果逐 OID 落库，默认重跑跳过当前代次 PASS，重查未检查/ERROR/RESIDUE。
发现部分残留同时另一查询报错，保存 RESIDUE 并在详情保留错误，便于重排清理；绝不能记 PASS。
单对象查询失败不阻塞其他对象检查，但最终验收不通过；进度写失败/中断/失锁停止当前运行。

每次重新进入 purge 都增加验收代次；保留 RESIDUE 供重新领取，处理成功时原子清除。
因此重清理后必须整批重新 verify，不能沿用旧 PASS。--restart 也开启新代次。
历史完成任务只有没有其他未完成任务时才能 restart，避免出现两个活动任务。

TSV 从持久化结果重新导出，包含当前代次错误/残留和全部延期项，不仅是本轮新结果。
临时文件写完、同步后原子替换；导出失败不写任务完成。报告不是唯一恢复依据。
verify 只能证明已授权范围目标无残留，不能证明没有误删其他对象；逐 key/云端审计本期暂缓。

## 执行锁

scan、task create、purge、verify、task defer、task resume 都取得同库命名锁；status 只读、不取锁。
可选 dry-run 同样取锁，以避免与真实删除/表初始化并行。

1. 锁名带数据库名的 SHA-256 摘要，不同 SP 数据库互不阻塞。
2. 专用 sql.Conn 持 GET_LOCK，不能用连接池随机连接执行锁操作。
3. 每 2 秒在原连接检查 IS_USED_LOCK == CONNECTION_ID；删除请求边界再次检查。
4. 失锁取消工作上下文，不自动换连接重获；退出显式 RELEASE_LOCK 后关闭连接。
5. 释放查询失败则丢弃该连接，不把可能仍持锁的连接归还连接池。

这是同一个 MySQL 写实例上的协作互斥，不是跨实例 fencing；不得切换到另一个实例继续并发运行。
锁丢失与请求发出之间仍有竞态，在途请求不能撤回。运维需避免同时用两个进度库清理同一物理范围。
